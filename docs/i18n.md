# Interface languages

BeautyDocs supports Polish (source), English, German, Spanish and French.

## How it works

- **UI text** uses gettext-style keys: the Polish string *is* the key.
  Client components call `const t = useT()` and write `t("Zapisz zmiany")`;
  async server components use `const { t } = await getServerTranslator()`.
  Values are interpolated with `{name}`: `t("Witaj, {name}", { name })`.
  A string missing from a catalog renders in Polish, never blank.
- **Catalogs** live in `lib/i18n/messages/{en,de,es,fr}.json`.
- **Chosen language** is stored in the `beautydocs_lang` cookie (drives
  rendering) and, when signed in, on the account (`users.interface_language` /
  `consumer_accounts.interface_language`) so it follows the person across
  devices. First visits fall back to the browser's `Accept-Language`.
- **Dates and numbers** in helper functions use `activeIntlLocale()` instead of
  a hard-coded `"pl-PL"`.

## Medical questionnaires and consents

Published template versions stay Polish and immutable. Translations are an
overlay in `apps/api/app/i18n/form_content/{lang}.json`, keyed by the **exact**
Polish source text (`app/services/form_i18n.py`). If a template's wording
changes, the new text falls back to Polish until it is translated — a stale
translation of medical or legal text is never shown.

- `GET /public/tenants/{slug}/forms/{code}?lang=de` returns translated content
  plus `contentLocale`.
- The signed snapshot records `contentLocale` and `contentHash` (SHA-256 of the
  exact translated wording the client saw).
- Staff and clients viewing a signed document see labels in their own
  interface language; answers are keyed, so they are unaffected.

> The medical and legal translations should be reviewed by a qualified
> translator / the salon's legal adviser before relying on them in production.

## Adding or changing text

1. Write Polish in the component, wrapped in `t(...)`.
2. Run `node scripts/i18n-messages.mjs` — it lists strings missing per language.
3. Add the translations to each `lib/i18n/messages/*.json`.
4. `npm run test:i18n` fails if any string or `{placeholder}` is missing.

For form content, add the new Polish source → translation to each
`apps/api/app/i18n/form_content/*.json`; `tests/test_form_i18n.py` checks that
every provisioned question, consent and legal text is covered.

## Not translated (intentionally)

- `/regulamin` and `/polityka-prywatnosci` — the binding Polish legal texts.
- Data entered by salons (service names, descriptions, job titles other than
  the defaults).
